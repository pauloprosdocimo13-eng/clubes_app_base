📋 PROMPT MAESTRO: PROYECTO APP CLUBES (MULTI-SABOR)

ROL: Eres un experto Senior en Flutter y Firebase. Estamos desarrollando una plataforma "Marca Blanca" (White Label) para crear Apps de Clubes Deportivos de forma masiva.

ARQUITECTURA DEL PROYECTO:

    Multi-Sabor: El código es único. La personalización se inyecta mediante la clase ConfiguracionApp (colores, logo, nombre, prefijos de BD).

    Puntos de Entrada: Existen main_generico.dart, main_guemes.dart, etc., cada uno inicializando su propia configuración y firebase_options.

    Base de Datos: Firestore (NoSQL). La estructura es dinámica y soporta múltiples deportes ("Tiras") dentro de una misma app (ej: Baby, Futsal, Femenino).

ESTADO ACTUAL DEL CÓDIGO:

1. Archivos Clave:

    lib/configuracion/configuracion_app.dart: Clase base para definir los estilos y datos del club.

    lib/pantallas/pantalla_seleccion.dart: Pantalla inicial. Lee configuracion/general de Firebase para listar los deportes activos.

    lib/pantallas/pantalla_inicio.dart: Dashboard del Usuario. Muestra botones dinámicos según los módulos activos (tienda, sorteos, minuto_a_minuto).

    lib/pantallas/pantalla_login_admin.dart: Login con Auto-Instalación/Reparación de BD (si falta configuración, la crea).

    lib/pantallas/pantalla_admin_dashboard.dart: Panel de control. Filtra botones según módulos activos.

2. Módulos Implementados:

    Deportivos: Partidos (con carga de goles por categoría), Jugadores, Rivales, Minuto a Minuto (Vivo/Historial).

    Institucional: Noticias, Avisos, Galería, Publicidad.

    Gestión: Socios (Padrón), Espacios (Reservas).

    Comercial (NUEVOS):

        Tienda Oficial: Catálogo de productos con botón de "Pedir por WhatsApp".

        Rifas/Sorteos: Sistema completo.

            Admin: Crea rifa, gestiona grilla de números (asigna nombre a vendidos), realiza sorteo con animación ("Bolillero").

            Usuario: Ve grilla en tiempo real, toca número libre -> WhatsApp para reservar.

3. Lógica Avanzada Implementada:

    Notificaciones Push: Integradas con Flutter (firebase_messaging) y Backend Node.js (Cloud Functions) que detecta goles/partidos finalizados.

    Admin UX: Los formularios (pantalla_admin_formulario_partido.dart) usan SharedPreferences para recordar la última fecha/torneo seleccionado.

    Sorteo Realista: El bolillero solo elige ganadores entre los números vendidos.

ESQUEMA DE BASE DE DATOS (FIRESTORE):

    configuracion/general:

        menu_deportes: Array de objetos {id, titulo, categorias[]}.

        modulos_activos: Map {tienda: bool, sorteos: bool, institucional: bool...}.

    partidos: Colección global filtrada por deporte_id.

    tienda: Documentos con {titulo, precio, imagen_url, activo}. Requiere índice compuesto (activo desc, titulo asc).

    sorteos: Documentos con:

        compradores: Mapa { "00": "Juan Perez", "14": "Maria" }.

        numeros_vendidos: Array de ints [0, 14] (para consultas rápidas).

        ganadores_lista: Historial de premios sorteados.

        cantidad_numeros: 100, 200, 333, etc.
